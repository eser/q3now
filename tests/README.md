# Wired/q3now test inventory

This directory contains two deliberately separate evidence layers:

- **Host subsystem contracts** are native, asset-free executables orchestrated by CTest.
- **Process and visual gates** boot a product binary and own their explicit fixture/content setup.

`make test-host` is the canonical host command. It fails when the configured tree contains no `host-only` tests; `make check` and therefore the release target consume the same command.

Every host test has a 30-second timeout. A test target must compile the owned production algorithm/source rather than a test-only reimplementation; production/runtime targets must never link a test framework. `wired_curve` now compiles the owned source with the production `q_shared.h` configuration and explicitly does not enable its standalone fallback. This inventory still has seam debt: `wired_scene_eval` and `wired_scene` use their source files' standalone fallbacks, while `mdl_anim` exercises a header through a separate test translation unit. Those remaining modes are contracts for the owned logic, not proof that the shipped engine translation unit was linked and executed unchanged.

## Commands

```sh
make test-host
ctest --test-dir build/release --output-on-failure --no-tests=error -L host-only
ctest --test-dir build/release --output-on-failure -L owner.wired-scene
ctest --test-dir build/release --show-only=json-v1
```

`BUILD_TESTING=OFF` is the production-only configure boundary: host test targets are not created and no test dependency may be required.

## Visual renderer gates

`tests/visual-render-features.sh` owns computed pixel/log oracles rather than human-only screenshot inspection. In addition to GTAO, Forward+, viewport, alpha-tested shadow, scene and chromatic modes, the dynamic-light cohort now has two distinct contracts:

- `--mode dlight-shadow` captures shadow-on A/A, shadow-off B and no-light frames inside one engine/map/camera/resource generation. It requires bounded same-config noise, a visibly lit receiver, localized cast-shadow darkening, and rejects whole-frame dimming.
- `--mode dlight-shadow-lifecycle` runs K=4/four synthetic lights, requires the exact `4 lights x 6 = 24 passes/frame` producer row, a device-bounded atlas, a live on-to-off resource rebuild, post-toggle screenshots, zero unexpected VUID/crash and controlled shutdown. It is lifecycle evidence, not a multi-light style or GPU-time claim.
- `--mode entity-occlusion` asks whether a world-space entity survives the world draw. It captures the same fixed camera three ways — `r_drawWorld 0`, plain, and `r_drawEntities 0` — learns which tiles the entity occupies from the world-off frame instead of hardcoding them, and requires those specific tiles to still move when the world is drawn. The negative control is the point: "the world-on frame is not empty" is satisfied by the world alone, so the gate compares entity-present against entity-suppressed with the world drawn in both. Defaults target the TASK-177 repro (`EO_MAP=arenam3`, `EO_POS`, `g_gametype 6`), all overridable by environment. It detects that a visible entity stopped being visible; it does not attribute the cause.

`tests/dlight-shadow-gpu-budget-check.sh` is the companion cost authority. Five fresh fixed-camera processes measure the no-op interval and K=1..4 through a RAL-owned timestamp query pool. Every active case binds its atomic `samples=200 / active / K / 6K passes / gpu-ms` row to the exact CPU producer, while the self-test rejects missing pools/samples, wrong K/pass metadata, off-path work, invalid ordering, non-scaling timestamps, validation errors and provenance/result corruption. The sweep reports real GPU milliseconds for the later default-K decision; it does not make that product/readability choice itself.

The former separate-process dlight comparison is intentionally retired because cold renderer/resource drift could counterfeit the A/B signal. `--mode selftest` contains the assertion-level no-shadow, global-dim and unstable-noise rejection teeth.

## Sanitizer lane

`make test-sanitize-host` configures a separate `build/sanitize-host` tree and
builds only the `host_tests` aggregate. Every host contract is compiled and
linked with fail-fast AddressSanitizer + UndefinedBehaviorSanitizer; production,
game-VM and WASM targets are not instrumented. Leak detection is disabled so
the lane remains portable across supported Clang/GCC hosts; bounds, lifetime,
alignment, integer and undefined-behavior failures remain fatal. CTest writes
the durable machine-readable result to
`build/sanitize-host/host-sanitizer-results.xml`.

The sanitizer-only `sanitizer_runtime_contract` intentionally executes one
heap-use-after-free and one signed-overflow probe in child processes. It passes
only when both children exit nonzero with the expected ASan/UBSan diagnostics;
this prevents an ignored compiler flag or missing runtime from turning the lane
into a vacuous green.

```sh
make test-sanitize-host
ctest --test-dir build/sanitize-host --output-on-failure --no-tests=error -L sanitizer.asan-ubsan
```
